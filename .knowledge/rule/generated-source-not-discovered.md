---
id: rule:generated-source-not-discovered
type: rule
title: Generated Source Is Not Discovered
---
Discovery skips any Go file carrying this tool's own generated header, whatever the file was named.

```yaml
status: implemented
source:
  - requirement:action-request-binding
  - implementation 2026-07-30
applies_to:
  - route discovery of concept:route-discovery, which feeds concept:openapi-generation
  - the type and call-site analysis of rule:request-model-discovery
key: the header comment before the package clause, matching a recognized prefix and ending 'DO NOT EDIT.'
recognized:
  own: 'Code generated by tinybind', covering every artifact this module writes
  registered: further prefixes a run declares, for a framework that brands its own generated files
  pairing: the emitter reports the prefix of the header it writes, so a registered string cannot drift from the header itself
  ending_required: a registered prefix still needs the conventional ending, so the registration cannot widen into any leading comment
why_header_not_name:
  problem: a fixed list of output names cannot cover requirement:custom-framework-generation-profile, where the caller chooses the file name
  effect: the generated registry of a route tree registers every page, so a name-keyed filter left those registrations discoverable
  observed: analyzing a route root put every page route and the action endpoint of requirement:template-server-functions into an OpenAPI document
why_prefix_configurable:
  reported: downstream verification 2026-07-30, from a framework whose header reads 'Code generated by <framework> via TinyBind'
  gap: keying on this module's own prefix covered a renamed output file but not a rebranded header, which is the same leak under a different name
  correction: the earlier claim that a header key covers a framework's own output holds for the file name only; the header itself had to become part of the contract
foreign_generated_code:
  rule: another tool's generated file is still discovered
  why: its registrations are the application's own API surface, and dropping them would remove routes from a document with nothing said about it
  boundary: this rule is about not reading back what tinybind wrote, not about generated code in general
related:
  - requirement:action-request-binding
  - requirement:template-server-functions
  - concept:route-discovery
  - concept:openapi-generation
  - rule:request-model-discovery
  - rule:generated-source-self-contained
```
