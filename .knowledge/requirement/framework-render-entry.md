---
id: requirement:framework-render-entry
type: requirement
title: Framework Render Entry
---
Let a framework choose the call a generated handler renders through, including whether the request reaches it, without replacing a whole template.

```yaml
priority: must
status: implemented 2026-07-30
source:
  - downstream framework integration request 2026-07-30
  - requirement:generated-route-registration
  - requirement:custom-framework-generation-profile
problem:
  root_cause: Symbols repoints a package but never a signature
  fixed_call_shapes:
    - '<RuntimeAlias>.Render(w, fragment, options...)'
    - '<RuntimeAlias>.RenderChain(w, wrappers, leaf, options...)'
  renaming_only: Emitter.RenderFunc and its siblings rename generated declarations, not the calls generated code makes
  downstream_effect: a framework whose response entry needs the request cannot use the symbol layer at all and falls back to replacing the handler block, the composer file, and the registry file
  why_request_needed: bot-mode selection, streaming choice, compression negotiation, document shell, and the error page all read the request
precedent:
  error_entry: the handler already calls WriteError(w, r, err), so the request is in scope and the error entry takes it
  argument: the reason the error block exists, that a framework must be able to build its own error value, applies unchanged to the render call
  asymmetry: today the entry that writes a failure takes the request and the entry that writes the page does not
implemented:
  render_block:
    name: render
    joins: the imports, convert, error, and handler blocks of requirement:generated-route-registration customization
    written_in: the registry handler body and the composer file
    model: the in-scope writer, request, wrappers, leaf expression, and options identifiers, so an override composes its own call
    chain_helper: a chain field reading nil where no wrapper exists, added after a documented override emitted an empty argument for a page with no ancestor layout
    request_in_handler: already in scope, so exposing it costs nothing and changes no default output
  composer_entry:
    problem: the composer takes io.Writer and no request, so a render block override there has no request to pass
    settings: RenderWriterType and RenderRequestParam on the emitter
    default: io.Writer and no request parameter, so default output is byte-identical
    imports: the composer imports what its own signature names, so a writer qualified by io, by the request package, or by the runtime needs no further configuration
failure_entry:
  reported: downstream verification 2026-07-30
  gap: BadRequest and Problem were symbols while the call writing the failure was the fixed name WriteError, so a framework spelling it otherwise needed the handler block
  implemented: Symbols.WriteError, defaulting to the current name
  scope: a name, not a shape; the entry already took the request, which is the asymmetry this requirement was named for
fixed:
  writer_default: io.Writer stays the default writer type
  why: buffer rendering is load-bearing, per the buffering rule of decision:script-free-render-mode, static export, and the func(io.Writer, Params) error shape of requirement:html-component-api
  runtime_contract: api:render-html-chain keeps its own signatures; this requirement changes what generated code may call, not what the shipped runtime accepts
gain:
  downstream: the three-template replacement collapses to one block override plus emitter settings
  upstream: one more named block, no change to any generated byte
acceptance:
  - a framework whose entry is func(w http.ResponseWriter, r *http.Request, wrappers, leaf) reproduces its handler and composer by overriding one block and setting the composer parameters
  - generation with no setting produces the same source as before the block existed
  - a rung 3 handler still renders into a buffer through the default composer
  - an override producing unparsable Go still fails naming the template and the route path
related:
  - requirement:generated-route-registration
  - requirement:colocated-route-logic
  - decision:framework-integration-seams
  - api:render-html-chain
  - data:generator-options
```
