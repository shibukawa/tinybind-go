---
id: decision:dynamo-single-table-scope
type: decision
title: Single-Table Design Is Out Of Scope
---
Generation assumes one struct owns one table, and only the table definition and the typed query decode assume it; the codec does not.

```yaml
status: accepted as a non-goal
decided: 2026-07-31, before secondary index tags exist, which is the last moment it costs nothing
what_assumes_one_table:
  table_definition:
    problem: <Type>Table returns one definition per type, so several types sharing a table produce several descriptions with nothing checking that they agree
    effect: a migration applying them as written would create or patch conflicting descriptions of one table
    owner: decision:dynamobind-table-definition
  typed_query_decode:
    problem: a query over a shared table returns mixed entity types, and a typed read decodes every item as one type
    effect: another entity's item is a decode error at best, and a partly filled value where attribute names happen to overlap
    deeper: dispatching on a stored discriminator is the runtime type lookup decision:dynamobind-static-dispatch removed on purpose, so supporting it reopens that decision rather than adding a tag
what_does_not:
  codec: EncodeItem and DecodeItem map one struct to attributes and have no opinion about who else stores items in that table
  key_builder: ItemKey names two attributes, and generic PK and SK names are a tag away
  consequence: a single-table user keeps the codec and the key builder, which is most of the generated bytes, and hand-writes the table definition and the read dispatch
secondary_indexes:
  effect: the deferred index tag is defined for the multi-table model only, per rule:dynamo-tag-options
  overloaded_index: an index whose partition key means one thing for one entity and another for the next has no per-type tag form, and inventing one is what this declines
if_revisited:
  needed: a discriminator attribute, a type registry keyed on it, and a table definition owned by a set of types rather than by one
  cheaper_middle_ground: let several types declare one shared definition without discriminator dispatch, which closes the definition conflict alone and leaves reads hand-written
related:
  - decision:dynamobind-table-definition
  - decision:dynamobind-static-dispatch
  - rule:dynamo-tag-options
  - requirement:dynamobind-product-goals
```
