---
id: decision:framework-integration-seams
type: decision
title: Framework Integration Seams
---
Accept the downstream integration requests that widen a customization seam already present, and refuse the ones that would move a contract an author writes against.

```yaml
source:
  - downstream framework integration request 2026-07-30
  - requirement:custom-framework-generation-profile
review_gate: accepted 2026-07-30, implemented the same day
finding:
  reported: Symbols can repoint a package but never a signature
  evidence: generated code calls Render(w, fragment, options...) and WriteError(w, r, err) in fixed shapes, while Emitter.RenderFunc and its siblings rename only the declarations generated code emits
  consequence: a framework whose response entry needs the request could not use the cheapest layer and replaced the handler block, the composer, and the registry
  verdict: the finding is correct and names the one axis the three customization levels of requirement:generated-route-registration never covered
accepted:
  - what: requirement:framework-render-entry
    value: highest, because it is what forced the three-template replacement
    cost: one more named block and two emitter settings, with no change to any generated byte
    status: implemented 2026-07-30
  - what: requirement:router-type-independence
    value: high, because the conflation of router and request package has no defence
    cost: four symbols with the current defaults
    status: implemented 2026-07-30
  - what: requirement:optional-query-parameter
    value: high, because the template language already spells the optional type the decoder refuses
    cost: one decoder branch
    status: implemented 2026-07-30
  - what: requirement:action-request-binding
    value: medium, and it converts an OpenAPI exclusion from a side effect into a stated filter
    cost: discovery reaches a new set of entry points
    status: implemented 2026-07-30
  - what: requirement:external-action-resolution
    value: medium, and the resolved map is already a compile option
    cost: one hook on the integrated generation path
    status: implemented 2026-07-30
deferred:
  interface_or_generic_mux:
    offered: default the registry parameter to a one-method router interface or a type parameter
    why_deferred: requirement:router-type-independence already lets a framework name its own router type, and decision:stdlib-servemux keeps the concrete stdlib type as the default
  script_free_mode_sequencing:
    request: implement the second phase, where a form posts to the page and answers 303, so an action works with no browser runtime
    design_status: already decided in decision:script-free-render-mode and the script_free lowerings of decision:server-action-lowering; nothing about the design is contested
    verdict: a scheduling request rather than a design change, so it changes priority and not this catalog's shape
    stated_because: a downstream acceptance condition requiring a script-free page cannot be met by a route using actions until the phase ships, and that dependency is invisible in a design that reads as complete
implementation_findings:
  mechanism_correction:
    was: the binder gap was attributed to discovery being driven by user-written registrations
    is: request model discovery reads every api:bind call site of the package it analyzes and consults no registration; the gap was that no run analyzed a route package
    consequence: the fix is a package list rather than a registration-site list, and requirement:action-request-binding records both readings
  openapi_leak:
    found: covering the route root exposed that the generated registry is itself a discoverable registration site, so every page route and the action endpoint entered an OpenAPI document
    fixed: rule:generated-source-not-discovered, keyed on the generated header rather than on a list of output names
    reading: the exclusion requirement:template-server-functions refused to leave as a side effect had in fact never held once discovery reached the registry
  render_block_argument:
    found: the documented override wrote an empty argument for a page with no ancestor layout
    fixed: a chain field on the render call, reading nil in that case, so an entry taking a chain needs no branch
downstream_verification:
  when: 2026-07-30, against the shipped release rather than the plan
  confirmed: all five accepted items, with the integration collapsing to symbol settings plus one render block; the handler, composer, and registry templates all stay built-in
  withdrew_generics: the downstream retracted its own type-parameter request, because a verbatim MuxType lets it name an exported Router interface and a type parameter would require the whole registry template for one avoided boxing
  withdrew_error_block: the default decoder error value already fits a framework whose Problem type matches, so the error block override the earlier reading assumed is unnecessary
  found_two_gaps:
    branded_header: the header filter recognized this module's prefix only, so a framework branding its generated files reproduced the OpenAPI leak; closed by registered prefixes and Emitter.GeneratedHeader, per rule:generated-source-not-discovered
    write_error: the failure entry was still a fixed name beside two symbols; closed by Symbols.WriteError, per requirement:framework-render-entry
  reading: both gaps are the same finding as the original one, found one layer further in; a seam is only as wide as its narrowest fixed string
confirmed_unchanged:
  reported_as_sufficient:
    - generated file naming through the component suffix, decoder output, and registry output settings
    - reserved file name configuration
    - Generate returning files rather than writing them
    - Emitter.Clone
    - action hash determinism
    - the htmlbind signature and action reference readers
  meaning: the integration exercised each of these and needed no change, so they are load-bearing as specified rather than merely unchallenged
principle:
  widen: a seam whose default output stays identical and whose contract stays the caller's
  refuse: a change to the shape an author's own Go is written against, per the fixed set of decision:action-lowering-profile
later_rounds:
  live: decision:live-integration-seams applies this principle to the live runtime, reported 2026-07-31
  components: decision:library-component-seams applies it to the component and asset seams, reported the same day
  runtime: decision:update-runtime-ownership-seams applies it to the browser asset and the protocol names, reported 2026-08-01; its mux item is this round's deferred interface_or_generic_mux found again in the runtime package, where no MuxType escape exists
related:
  - requirement:generated-route-registration
  - requirement:custom-framework-generation-profile
  - decision:route-feature-ownership
  - decision:script-free-render-mode
```
